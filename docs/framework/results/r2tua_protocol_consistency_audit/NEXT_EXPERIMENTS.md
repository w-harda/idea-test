## 完整严格方案（成本显著更高）

明确两组威胁模型，分别报告：
A. 生成式Image-only：训练期可见同一个Source及配对训练数据，Test不读正确配对/Target反馈；G(I)与需要prompt的方法分别标注额外信息。
B. Joint或Test迭代：共同声明图像预算、合法文本编辑与配对/源梯度权限；不同文本语义预算无法简单用“1词=K字符”折算，保留原生设置并增加合法性统计。

固定Victim文件、完整测试身份、原生评分/Top128、同一Clean桥；用统一CPU验证器核验所有攻击输入。
对齐实际Train数据身份和样本量，记录Adam更新/源前后向/MLM调用/JVP/图库刷新，而非以同Epoch数宣称等计算。
保留各算法核心Loss与原始更新，不以公平性为由改写Baseline。必要改动应单独命名并重新做官方保真审计。
R²TUA8/255和16/255分别成表；Table3相同可见源集合、元学习预算、不可见Target；不能将IRRA→APTM硬拼其不存在的APTM行。
正式比较使用预先固定Checkpoint，Validation选择规则独立于Test，最好增加多随机种子；无置信区间不声称微差显著。

## 哪些变化要重生成/重训练

| 变化 | 已有产物能否直接复用 | 最小额外成本 |
| --- | --- | --- |
| 仅文档/来源标签修正 | 可以，保持旧结果不动 | CPU |
| 同Victim同桥，仅统一结果格式 | 可以 | CPU |
| 取得另一组可比RGB产物，统一Victim评分 | 先核验像素空间/身份/预算 | 图像/文本编码和排名 |
| 改Victim Checkpoint但只研究固定攻击迁移 | 冻结产物可用；重新评分需声明新目标 | 编码与排名 |
| 改图像尺寸/原始投影空间 | 不能无条件重采样后称同攻击 | 协议核验；可能重生成 |
| 8/255改16/255或Test迭代预算改变 | 旧产物只能作低预算参考，不能乘2改名 | 重新生成或原生迭代 |
| 改Source、配对/prompt权限或训练数据 | 固定产物可作旧协议，不能宣称新白盒 | 通常需重训练/重生成 |
| R²TUA作者适配未公开 | 无法保证严格复现 | 先补证据，保持UNKNOWN |
